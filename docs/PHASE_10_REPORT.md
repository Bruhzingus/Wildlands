# Phase 10 implementation and verification

Implemented on 2026-10-19, preserving the existing simple olive game UI, native mouse capture, camera-relative movement and all prior combat/progression/exploration/boss systems. Phase 03 is not marked complete by this request.

PHASE: 10 — UX, upgrade pause and sound

What changed: Strengthened the health/XP hierarchy with an explicit health heading and critical status, added numeric party HP and non-color critical marks, a six-simulation-second permanent-faint notice followed by persistent critical warnings, and static cooldown-ready tiles/announcements. Upgrade cards keep their numeric descriptions, rank badges and restrained rarity accents, and now use local SVG icons for attack/item/training categories. Title and pause settings include separate Sound/Music sliders, Camera shake, Hit pause and Reduce flashes. The existing keyboard selection/focus flow is preserved.

Added original procedural synth cues and a gentle eight-note ambient motif with no audio downloads or copyrighted recordings. Audio unlocks lazily during a user gesture. Quiet defaults are 18% sound and 7% music. Combat cues are globally throttled, voices are bounded, and high-importance cues can replace low-importance voices. Pause/blur stops combat and ambient audio without queued catch-up. Level/victory/defeat/selection feedback sounds once; paused frames do not replay it. An explicit blur also cancels an already-paused menu cue. Restarts reuse one graph and full disposal closes it.

Special activation and incoming boss damage get minimal deterministic shake and 30/40ms hit pause. Ordinary automatic hits do not shake. Controls remain responsive: action taps during a stopped frame are buffered once, Escape remains immediate, all simulation clocks freeze together, and the camera target is restored exactly after rendering. The shake never alters camera alpha/beta or simulation RNG. System reduced motion disables impact shake/hit pause and damage flashes. Reduced flashes suppresses player-damage flashes independently; follower danger is communicated through its own HP/warnings.

Changed files: `src/game/Game.ts`, `src/game/Simulation.ts`, `src/game/combat/projectiles.ts`, `src/game/settings.ts`, `src/game/audio.ts`, `src/game/feedback.ts`, `src/data/feedback.ts`, `src/ui/UI.ts`, `src/ui/upgradeIcons.ts`, `src/style.css`, `index.html`, `tests/audio.test.ts`, `tests/feedback.test.ts`, `tests/presentation-events.test.ts`, `tests/save.test.ts`, `tests/upgrade-icons.test.ts`, `tests/browser/phase10.spec.ts`, `tests/browser/variants.spec.ts`, `README.md`, `GAME_DESIGN_AND_ROADMAP.md`, this report.

Why the approach is maintainable: The simulation remains authoritative. Hit events retain their attacker identity through projectiles/contact/rings, and permanent faints emit one semantic event. `Simulation.choose()` reports whether a choice actually applied so rejected/repeated input cannot play acquisition feedback. Audio owns its graph and scheduler without listeners or timer queues. Impact feedback owns only bounded presentation timers/offsets. `Game` coordinates pause/input/lifecycle. Settings retain their existing storage key, sanitize new fields and merge partial writes without losing camera preferences or unrelated save data. UI uses shared attack/item data to select icons; it does not decide combat or upgrade effects.

Tests run: Baseline `npm test` passed 145 cases; `npm run typecheck` passed; `npm run test:browser -- tests/browser/game.spec.ts --grep 'real WebGL gameplay' --output artifacts/browser/10-baseline` passed. Final `npm test` passed **168/168**; `npm run typecheck` and `npm run build` passed. The build retains the existing Babylon chunk-size warning (approximately 6.14 MB, 1.36 MB gzip). Full browser and compiled smoke results are recorded below.

Browser smoke steps: Verified a locked/zero-node audio graph before interaction, gesture unlock, a nonzero actual Web Audio signal through an analyser, saved volume/comfort/camera settings, bounded voices, quiet music scheduling, pause/blur cancellation and graph reuse across three real restarts. Verified critical HP, numeric follower HP, real poison-induced follower faint, ready feedback and numeric/icon upgrade cards; complete choice pause and exactly one selection cue. Manually advanced real Game frames with native pointer lock to verify bounded hit pause buffers a jump, restores the camera target/angles, and respects independent comfort controls. With system reduced motion enabled, actions and one-shot attacks still work while added impacts/flashes are suppressed. Existing native capture loss/denial/cancellation, movement, upgrade, boss/endless, sprites, world bars and mobile menu regressions are included in the combined run.

Known limitations: The 30-second comprehensibility and relaxing feel targets still require human observation/listening sessions. Automated tests verify generated signal and gains, not subjective loudness on speakers/headphones. Audio may remain silent when the browser/device does not provide or unlock Web Audio; this does not interrupt gameplay. Existing character art/fallback coverage is unchanged. Target-hardware GPU performance and full mobile/controller input remain future phases.

Balance / performance impact: No attack damage, XP, recruitment gates, enemy weights or boss HP changes. Hit pause deliberately stops simulation time briefly on selected impacts; presentation timers use real active time and never queue a pause/resume burst. Special and boss impact requests share a 200ms cooldown, maximum 45ms stop, maximum 0.1 world-unit displacement, and 160/190ms shake duration. Audio caps at twelve voices: three persistent bus/limiter nodes plus at most 24 oscillator/envelope nodes. Eight audio tests cover rate limits, priorities, lifecycle, muting, autoplay failures and optional-device behavior. Seven impact tests cover bounds, event deduplication, pause reset, independent toggles, reduced motion, deterministic offsets and no state/RNG mutation. Three integration tests verify actual attacker attribution, one-shot faint notification and valid-choice reporting. Settings/icon tests cover migration, corruption, storage denial, all 151 species' attack patterns and all passive item definitions.
