# Phase 14 implementation and verification

Implemented on 2026-10-19. The selected direction is collecting starter partners and achievements, with finite optional expedition/rules unlocks and no permanent stat grind.

PHASE: 14 — Meta-unlocks, achievements and save migration

What changed: Added ten accomplishments and a compact collection library with all fifteen starter partners, explicit requirements, numeric progress, earned rewards and local JSON backup/import tools. Accomplishments cover three-minute survival, four living members, four discoveries, leader plus follower evolution in one run, two living Poison types at fifteen minutes, one hundred cumulative Rocket defeats, Mewtwo victory, victory without a follower faint, eight distinct relics, and twenty actual minutes of endless after victory. Starter collection is the primary reward. Side rewards unlock four existing epic relics, eleven single-stage recruit candidates, two fixed-seed routes through the existing Wildlands, and optional Quickened / No healing rules. No new terrain or alternate boss is claimed; those remain phase 15.

The version-two save keeps the original storage key so version-one players retain their partners, scores, wins, run counts and legacy settings. Existing players retain all thirty-six relics and the full previously available recruit pool. A recorded historic victory grants only the victory accomplishment; migration does not invent team composition, faint or Rocket history. Fresh players have thirty-two relics available and earn the four finite side unlocks. Imported/exported saves use the same sanitizer and schema migration. Import requires recognized partner-collection data, validates JSON/version/size, presents the incoming partner/achievement/run counts, and requires a visible “Use imported save” action; Cancel and rejected files leave progress untouched. Storage denial leaves a playable in-memory session.

The run tracker receives actual semantic enemy-death events, observes authoritative party/evolution/POI/item state, and checkpoints deltas under one session run ID. It counts a victory followed by endless and defeat as one game and one win. Rocket deaths are deduplicated, score counters only increase by uncommitted differences, and history is bounded. Endless duration uses the exact authoritative transition time, so the achievement cannot trigger after only five minutes of endless. New unlock policies are copied when a run starts; earning a collection reward does not mutate an active run’s offer pool. Root integration records earned results before rendering the result page and displays actual rewards rather than the former unconditional new-starter message.

Changed files: `src/data/unlocks.ts`, `src/game/save.ts`, `src/game/achievements.ts`, `src/ui/UnlockLibrary.ts`, `src/ui/unlocks.css`, `tests/meta-progression.test.ts`, `tests/save.test.ts`, `tests/browser/phase14.spec.ts`, this report. Shared integration by the coordinating agent: `src/game/Game.ts`, `src/game/Simulation.ts`, `src/game/types.ts`, `src/ui/UI.ts`. Recruitment/item policy enforcement is shared with phase 11 in `src/game/systems/progression.ts`; gated recruit IDs come from `src/data/rosterContent.ts`.

Why the approach is maintainable: One data registry defines accomplishments, rewards and selectable route/rule descriptions. Saves sanitize unknown input at one boundary and migrate rather than replacing the old storage key. Progression has no combat-stat fields or independent clocks and does not control simulation. The tracker owns bounded session accounting and explicit snapshots/events. UI rendering and binding live in a separate module/CSS file, with child-local listeners and stale file-read guards. The existing game UI owns title/result placement and keyboard focus. Run configuration feeds existing seeded generation and combat systems.

Tests run: `npm run typecheck` passed during integration. `node --experimental-strip-types --test tests/meta-progression.test.ts tests/save.test.ts` passed **19/19** twice, including after final import hardening. Thirteen new meta tests cover old-save preservation, finite rewards/catalog coverage, damaged fields, export/import, locked selections, precise survival boundaries, living members, same-run evolution, Poison/discovery/distinct-relic conditions, duplicate Rocket events across runs, exact endless duration, victory/endless deduplication, faint history, bounded accounting, storage denial and rendered library requirements. Existing six save/settings tests remain green, including the graphics-default expansion.

Browser smoke steps: `npm run test:browser -- tests/browser/phase14.spec.ts --output artifacts/browser/14-results` passed **3/3 in 18.1 seconds**. Verified all ten visible accomplishment entries and fifteen collection entries; malformed JSON rejection, incoming-save review and Cancel, valid version-one migration, imported partner on the actual title, all thirty-six legacy relics, exported JSON download and reload persistence. Exercised one hundred actual Rocket enemy deaths through `Simulation.damageEnemy`/`killEnemy` and the real event hook; earned Eevee appears on the following title. Defeated an actual test Mewtwo through its death path, verified earned result rewards, continued endless with native mouse capture, checked no achievement at 19:59.5 endless and completion at twenty minutes, then real player defeat and restart without duplicate games/wins/Rocket totals. Verified newly available rules/routes, persisted Pinewood seed 46837 and Quickened rules in an actual run, then returned to Standard. At 390px, the open collection has no horizontal overflow. Screenshots: `artifacts/browser/phase14-library-mobile.png`, `artifacts/browser/phase14-collected-partners.png`.

Known limitations: These are controlled QA fixtures, not evidence of twenty-minute human survival or subjective replay balance. Route unlocks are reproducible seeds of the existing world, not new maps. Full original starter collection has fifteen options; additional starter rosters would require explicit content design. Save data is local and user-editable, with no account/cloud synchronization or anti-cheat promise. Export covers progression and legacy save fields; separate live audio/camera/graphics preferences retain their existing settings key. No deployment was performed.

Balance / performance impact: No permanent damage, HP or attack-speed bonuses. Four existing epic relics and eleven single-stage recruit candidates are finite new-player side unlocks; old players retain their available pools. Quickened is opt-in +20% enemy movement speed. No healing disables field healing/regeneration while max-HP upgrades/evolution still add the newly gained HP capacity. All rewards can be inspected before earning them. Save writes happen on new accomplishments, run checkpoints and deliberate settings/import actions; progress observations do not write storage each frame. Kill deduplication retains at most 2,048 recent IDs and save run history retains at most 32 records. Target-hardware GPU performance is covered separately by phase 13, not established by these browser tests.

Next recommended phase: 15 — New maps, bosses and replay hooks, after human balance/comfort review of the current finite collection and challenge rules.

Regression checklist: Existing starter IDs and prior local progress migrate; native FPS capture resumes from starter/Endless; A/D and camera behavior stay in the existing input path; menus still pause simulation; exact recruitment/evolution gates and permanent follower fainting remain authoritative; ordinary and gated item/recruit offers use the shared progression engine; Mewtwo death produces real victory and endless preserves the same run; no duplicate score accounting; malformed/foreign import cannot silently replace progress; simple olive UI and keyboard-compatible controls retained.
