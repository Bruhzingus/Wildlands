# Phases 10–14 handoff

Implemented on 2026-10-19 in the existing local Babylon/TypeScript game. The selected direction is starter collection and achievements, with automatic graphics for laptops and gaming PCs. Phase 03 and phase 15 are not marked complete.

PHASE: 10–14 — UX/audio, complete Kanto content, measured run telemetry, reliability and finite progression

What changed:

- Phase 10: stronger HP/XP hierarchy, numeric follower HP and faint/critical warnings, cooldown-ready feedback, numeric upgrade cards and local SVG icons; quiet original procedural sound/music with independent sliders; bounded optional shake/hit pause and reduced-motion support.
- Phase 11: 151 authored species loadouts, validated original Gen 1 typing/evolutions, complete actual encounter coverage, scarce late legendary elites, stronger evolution output, viable weak-species attacks, explicit stone/trade adaptations, six-variant content preview and offer/application unlock enforcement.
- Phase 12: deterministic headless multi-seed experiments, movement/build policies, complete level/damage/party/recruit/evolution/rarity/boss/upgrade-gap metrics, JSON/CSV/tables, replay fingerprints and an opt-in local recorder for real human sessions. Fresh-save and legacy pools are identified separately; health-assisted experiments are explicitly labeled.
- Phase 13: automatic/manual graphics, independent resolution/effect density, bounded development profiling, reduced per-frame allocations/DOM work, thirty simulated endless minutes, ten actual rendered restarts, above-budget crowded rendering and missing-art fallback checks.
- Phase 14: version-two save migration, fifteen collectible starter options and ten achievements, finite relic/recruit/route/rule rewards, collection library, reviewed local JSON import/export, accurate earned-result messages and one-run accounting across victory/endless/defeat. Existing saves keep their prior pools and settings. No permanent combat-stat bonuses.

Changed files: Detailed inventories are in [phase 10](PHASE_10_REPORT.md), [phase 11](PHASE_11_REPORT.md), [phase 12](PHASE_12_REPORT.md), [phase 13](PHASE_13_REPORT.md) and [phase 14](PHASE_14_REPORT.md). Shared integration changes `Game.ts`, `Simulation.ts`, `types.ts`, `UI.ts`, settings/style and package commands. The existing engine, combat, exploration and native input systems remain in use.

Why the approach is maintainable: Content uses shared attack archetypes, evolution/encounter registries and independent validation data. Simulation owns gameplay. Audio, impact feedback, graphics and diagnostics own bounded presentation state. Save migration/sanitization has one boundary; achievement tracking observes actual state and once-only deaths. Telemetry wraps the real simulation outside production code. Unlocks expand choices without a second stat-progression engine.

Tests run: Final combined verification is recorded below. Phase-specific reports retain exact individual commands, fixture conditions and artifacts. `npm run content:audit`, `npm run balance:telemetry -- --help` and `npm run profile:reliability` are reusable local commands.

Browser smoke steps: Full native mouse capture and relative-look regressions; correct camera-relative movement; capture loss/denial/cancellation; paused choices and numeric keyboard picks; actual sheets/world bars/attack windups; factions/map/boss/endless; sound signal/muting/lifecycle; independent comfort controls and reduced motion; saved/manual graphics; blocked storage; ten real restarts; overloaded scene/fallback; reviewed import/export and actual achievement/unlock/run-option paths. Independent content QA loaded all **906 species/variant pairs** through the live renderer with zero page errors. The opt-in telemetry recorder was exercised with real native capture and keyboard input.

Known limitations: Automated scripts do not establish human enjoyment, casual difficulty, subjective audio comfort or a minimum FPS on the user's GPUs. A real-session recording protocol is provided for those observations. The 30-minute stress evidence is headless simulation plus separate rendered crowd/restart tests, not thirty wall-clock rendered minutes. The two unlocked routes are fixed seeds of the existing Wildlands, not new phase-15 maps. Saves are local; export backs up progression, while live controls/audio/graphics use their existing settings key. No public deployment was performed.

Balance / performance impact: Curated bounded power replaces ID-derived variance; all 72 evolutions improve conservative equal-rank damage cadence by 6.06–77.23%. Recruitment times, maximum normal party, XP thresholds, director budgets and boss HP remain unchanged. Scarce birds/Mew reuse existing late spawn slots. Fresh players unlock four finite relic sidegrades and eleven single-stage recruit candidates; previous players retain access. Quickened adds 20% enemy speed and No healing removes field recovery only when selected. Long-session simulation memory stabilizes around 10.6MB; normal rendering entity/FX limits remain unchanged. Full numeric cohort and profiling evidence belongs in the phase 12/13 reports.

Next recommended phase: 15 — new maps, bosses and replay hooks, guided by recorded human playtests and hardware measurements.

Regression checklist: Continuous captured camera and correct A/D; no menu-time gameplay/audio replay; exact recruit/evolution gates; permanent follower faints; item/proc/entity caps; local asset fallback and disposal; readable boss tells and actual victory; endless state and score retention; corrupt/legacy save safety; no duplicate unlock/run awards; simple retro olive UI.

No new packages, external audio assets or deployment were introduced. The temporary production preview used for verification was stopped after completion.
